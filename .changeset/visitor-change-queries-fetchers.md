Query clients and router fetchers hold nothing for the next visitor. `identityChanged()` clears every query client the page made, cached, infinite and hydrated queries alike, and returns every fetcher to idle. In an app with a `keepAlive` route, a new identity epoch cookie does the same on the next read, through the client or through a query handle or fetcher the page kept from before: data goes at once, and mounted queries and fetchers hear of it once the current render is over. The router reloads the page on screen in place, shown as it was and pending until the reload lands. A query fetch or refetch, an infinite query's page fetch, a fetcher load, a navigation or `invalidate()` still loading loads once more for the new visitor, or answers as the reload the change started, and its promise settles once that answer is shown, or rejects if that load fails; a submit still posting finishes before the page reloads. A server that sets a new epoch on every response costs a bounded number of loads, never a loop. The epoch is read once per synchronous run, since a `document.cookie` read costs microseconds.
