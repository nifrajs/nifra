Experimental and unstable: partial prerendering, from the new `@nifrajs/web/ppr` subpath. With `createWebApp({ experimental: { ppr: partialPrerendering({ shellChecks }) } })`, a route whose backend half exports `shellLoader` streams a shell shared by every visitor, then each `dynamic` boundary as it settles. An app that does not import the subpath ships none of its server code.

- **Shells.** The shell loader (typed with `defineShellLoader`) receives params, locale, declared `variations`, the configured `origin` and the in-process `api`, never the request. A shell is shared only for a route that passed `compileShells` for this deployment, which refuses a shell reaching a request-scoped module, including `getContext()` or `tryGetContext()` from `@nifrajs/middleware/context-storage`; it takes the server build's `plugins`, such as `svelteBunPlugin("ssr")`. Any other route renders whole. `checkShellCanaries(app, paths)` requests each path with unique cookie, `Authorization`, header and query values and reports each one that reaches the shared shell, which catches visitor data an app keeps in module state.
- **Caching.** A shell older than the route's `revalidate` is served while one rebuild runs behind it; a failing rebuild keeps the old shell for up to ten times `revalidate` (at most a day); a shell loader's `notFound()` is remembered for 60 seconds, during which the route starts no hole; a route already building four shells renders further misses whole. With `shellAfterRequests: n`, a shell is built on its key's nth request and the earlier ones stream the page whole, each hole as it settles, so a path requested once never pays for a shell; `checkShellCanaries` requests a path until a shell answers. `shellVariations`, closed sets of query values, each select their own shell. `pprShells(app)` drops shells by tag, as a `createInvalidator` data cache, and reports admission and unsent-byte counters. A page cache such as `withISR` never stores a partially prerendered route's response, whichever way it rendered, since its holes are one visitor's.
- **Holes.** A route has 1 to 32 holes, each with a `boundaryLoaders` entry, named with 1-32 lowercase letters, digits and single hyphens, starting with a letter and not ending with a hyphen; a hole's `timeout` is 1 to 30000 ms. A hole that returns or throws a redirect or a status renders its error state, since the shell's status and headers are already sent. Hole HTML is checked on the server and inserted without running scripts, every script in the document is allowed by hash, and leaving the page cancels the holes still loading. Every hole loader runs under its own deadline and a per-process admission limit that stops admitting a boundary whose loaders keep running after their abort; a prefetch starts no hole. A client that stops reading gets its later holes as errors once its unsent bytes pass a per-response budget, and the slowest readers are cut off when the process's pass its own. Every limit is a default in `PPR_DEFAULTS`, overridable per app.
- **Routes.** `partialPrerendering({ origin })` gives `shellLoader` and the shell's `meta` the deployment's public origin, never a visitor's Host. A layout above a partially prerendered page may have a loader only as a `gate`, which runs to redirect or refuse and whose data reaches no response. In development, a shell with fewer than 200 characters of text warns, since Safari does not paint such a page until its last hole arrives, and so does a hole whose fallback renders empty.
- **Adapters.** `Hole` from `@nifrajs/web-react/ppr`, and `Hole` from `@nifrajs/web-svelte/hole` with `ui(Component, props)` from `@nifrajs/web-svelte/ppr`, place a hole and hydrate an interactive one as its own root. Both adapters render a hole's HTML with `renderFragment`.
