`nifra migrate layout` reads a config module path built with `resolve`/`join` from `node:path` on the config's own folder (`import.meta.dir`, `import.meta.dirname`, `__dirname`), or with `fileURLToPath(new URL(..., import.meta.url))`, as an entry, and re-points it when its module moves; `nifra check` reads `clientModule` the same way for NF-C028. A moved file's own-folder path is re-pointed even when the file itself stays. A test moves with the subject beside it (`x.test.ts` next to `x.ts`, or in `__tests__/`), with its `__snapshots__` file, instead of zoning on its own imports; one whose subjects land in different folders stays and is reported. Every `tsconfig*.json` at the app root keeps each file in, or out of, its program as before: an entry naming a moved file follows it, a folder or glob gains its twin under the zone folder (`src` -> `frontend/src`) where adding the whole zone folder would take in files it left out, and an excluded folder gains its twin in `exclude`. A sibling package in the same workspace that names a moved file, by a relative import or a path string, is reported; the migration never edits files outside the app.
