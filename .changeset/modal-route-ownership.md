A route opened in a modal through an intercept boundary now keeps the page and the target apart. `RouterState.intercepted` names the open boundary and the page's own path, while `path` stays the address-bar URL. An action, `invalidate()` or a mount refresh reloads the page under its own path and the target under the modal's, each with its own cache entry, and layout data is retained from the page's path, so a revalidation no longer renders the target as the page or caches one route's data under the other's URL. A target that fails a reload turns the boundary into an `"error"` state with a generic error instead of exposing its answer. A form with no action posts to the route that owns it: the target when it sits inside `data-nifra-boundary="<name>"`, otherwise the page. The result of an action posted to the target arrives as the boundary's new `actionData`, and the page's `actionData` stays its own. While the boundary is open, every adapter's route props - and so `useLocation`, `useSearch` and `useMatches` - describe the page underneath rather than slicing the target's URL against the page's route chain. Opening the modal keeps the page's scroll, a link to the page's own URL is never intercepted, and only one intercept boundary is open at a time. New `closeBoundary(name)` closes the modal by going back through the entries it added, or by replacing its URL with the page's when those entries are not in this tab's history.
